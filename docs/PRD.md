## 1. 제품 개요

**한 줄 요약:** 웹캠 하나로 전신 모션을 인식해 플레이하는 브라우저 기반 아케이드 게임

Motion Arcade는 별도의 하드웨어 구매 없이 브라우저와 웹캠(내장 포함)만으로 전신 움직임을 게임 입력으로 변환하는 인터랙티브 아케이드 플랫폼이다. TensorFlow.js의 MoveNet 모델을 활용해 실시간 포즈 추정을 수행하며, 4가지 장르의 미니게임을 통해 신체 활동과 게임 재미를 동시에 제공한다. 모든 영상 데이터는 사용자의 기기 내에서만 처리되며 서버로 전송되지 않아 프라이버시를 완전히 보장한다.

---

## 2. 문제 정의

### 해결하려는 문제

기존 모션 게임(Xbox Kinect, Nintendo Switch Ring Fit 등)은 전용 장비 구매가 필요해 진입 장벽이 높다. 반면 모바일 터치 게임은 신체 활동을 유도하지 못한다. 브라우저에서 추가 설치 없이 즉시 전신 모션으로 플레이할 수 있는 게임이 부재하다.

### 타겟 사용자

| 세그먼트 | 설명 |
|----------|------|
| 가족/친구 단위 | 집에서 함께 즐길 수 있는 파티 게임을 원하는 그룹 |
| 10대~20대 | 새로운 인터랙션 방식에 관심 있는 디지털 네이티브 세대 |
| 30대~40대 | 운동 겸 게임을 즐기고 싶은 직장인, 학부모 |
| 교육 현장 | 체육 수업 또는 방과 후 활동에 활용하는 교사 |

**공통 특성:** 스마트폰/태블릿/노트북 보유자, 별도 앱 설치 없이 링크 공유로 즉시 접근 가능한 경험 선호

### 사용자 페인포인트

1. **높은 진입 장벽:** 콘솔 모션 게임은 전용 하드웨어(컨트롤러, 센서, 본체) 구매가 필요하고 설치·설정 과정이 복잡하다.
2. **비활동적 게임 경험:** 현존하는 대부분의 브라우저 게임은 손가락/마우스 조작에 한정되어 있어 신체 활동을 전혀 유도하지 못한다.
3. **프라이버시 불안:** 카메라를 활용하는 서비스에 대한 영상 데이터 수집·서버 전송 우려로 사용 거부감이 존재한다.

## 3. 목표 및 성공 지표

### 비즈니스 목표

- **MVP 출시 (Phase 1):** 4개 미니게임이 포함된 완성된 웹 게임 런칭, Vercel을 통한 무료 배포
- **사용자 기반 확보 (Phase 2):** 소셜 공유 및 리더보드를 통한 바이럴 성장
- **수익화 기반 마련 (Phase 3):** 모바일 PWA 전환 후 광고/인앱결제 모델 검토

### KPI (핵심 성과 지표)

| 지표 | MVP 목표 | 3개월 목표 |
|------|----------|------------|
| DAU (일간 활성 사용자) | 50명 | 500명 |
| 평균 세션 시간 | 5분 | 8분 |
| 게임 완료율 (60초 완주) | 60% | 70% |
| 재방문율 (7일 내) | 20% | 35% |
| 카메라 권한 허용률 | 75% | 80% |

### MVP 범위 정의

**포함 (In Scope):**
- 웹캠 기반 실시간 포즈 인식 (MoveNet SINGLEPOSE_LIGHTNING)
- 캘리브레이션 화면
- 4개 미니게임: SpacePong, FruitSlicer, ObstacleDodge, JumpChallenge
- 게임별 60초 타이머 및 점수 시스템
- 로컬스토리지 기반 최고점 저장
- 반응형 UI (모바일/태블릿/데스크톱)

**제외 (Out of Scope):**
- 멀티플레이어 / 실시간 대전
- 온라인 리더보드 (서버 필요)
- 소셜 공유 기능
- 사용자 계정 / 로그인

## 5. 기능 요구사항

### Core Features (MVP)

#### 5.1 카메라 & 포즈 인식

| 기능 | 세부 스펙 |
|------|-----------|
| 웹캠 스트림 획득 | `getUserMedia` API, 640×480 해상도 기본값 |
| 포즈 감지 | TensorFlow.js MoveNet SINGLEPOSE_LIGHTNING, 17 keypoints |
| 프레임 처리 | frameSkip 옵션으로 성능 조절 (데스크톱: 1, 모바일: 2~3) |
| 오류 처리 | 카메라 거부/미지원 시 안내 메시지 + 재시도 버튼 |
| 미러 반전 | 화면에는 미러 표시, 포즈 계산은 원본 좌표 기준 |

#### 5.2 캘리브레이션

| 기능 | 세부 스펙 |
|------|-----------|
| 캘리브레이션 트리거 | 게임 시작 전 자동 실행 |
| 기준 데이터 수집 | 어깨 중심(centerX), 힙 Y 기준선(hipY), 어깨 너비(shoulderWidth) |
| 완료 조건 | 3초간 안정적 포즈 감지 후 자동 확정 |
| 재캘리브레이션 | 게임 중 언제든 메뉴에서 재실행 가능 |

#### 5.3 제스처 인식 (GestureRecognizer)

| 제스처 | 계산 방법 | 출력 범위 |
|--------|-----------|-----------|
| bodyX (수평 이동) | `(어깨중심X - 캘리브레이션centerX) / (화면너비/2)` | -1 ~ 1 |
| bodyLean (기울기) | `(오른쪽어깨Y - 왼쪽어깨Y) / 어깨간격` | -1 ~ 1 |
| isJumping (점프) | `힙Y 평균 < 캘리브레이션hipY × 0.8` | boolean |
| 손 위치 (x, y) | 손목 좌표 / 화면 크기 (정규화) | 0 ~ 1 |
| 손 속도 (speed) | 최근 5프레임 이동평균 속도 | 0 ~ ∞ |

#### 5.4 4개 미니게임

**SpacePong**
- 몸 수평 이동으로 우주선 패들 조종
- 공이 바닥으로 떨어지면 목숨 감소 (3개)
- 패들 히트 시 5점, 50점마다 속도 10% 증가
- 60초 제한 또는 목숨 소진 시 종료

**FruitSlicer**
- 양손 빠른 움직임 (speed > 0.3)으로 과일 슬라이스
- 15% 확률로 폭탄 등장, 슬라이스 시 목숨 감소
- 과일 슬라이스 성공 시 10점
- 3개 미스(놓친 과일) 누적 시 목숨 1 감소

**ObstacleDodge**
- 몸 기울기(bodyLean)로 장애물 파이프 사이를 통과
- 파이프 통과 시 10점
- 파이프와 충돌 시 즉시 게임 오버
- 시간에 따라 파이프 속도 및 빈도 증가

**JumpChallenge**
- 실제 점프(isJumping)로 장애물 회피
- 생존 시간(초) × 10 = 점수
- 시간에 따라 이동 속도 증가
- 장애물과 충돌 시 즉시 게임 오버

#### 5.5 점수 시스템

| 기능 | 세부 스펙 |
|------|-----------|
| 실시간 점수 표시 | HUD 상단 중앙, 네온 스타일 |
| 잔여 시간 표시 | HUD 상단 우측, 초 단위 |
| 게임 오버 화면 | 최종 점수 + 최고 기록 + 재도전/메뉴 버튼 |
| 기록 저장 | `localStorage` 키: `motionArcade_highscore_{gameName}` |

### Extended Features (Phase 2+)

| 기능 | 설명 | 위상 |
|------|------|------|
| 온라인 리더보드 | 닉네임 입력 후 서버 저장, 상위 10위 표시 | Phase 2 |
| 소셜 공유 | 점수 + 스크린샷 카드 생성, Web Share API 활용 | Phase 2 |

| 커스텀 아바타 | 색상/형태 변경 가능한 플레이어 캐릭터 | Phase 2 |
| 추가 게임 | 리듬 댄스, 복싱 등 장르 확장 | Phase 3 |

## 7. 사용자 흐름 (User Flow)

### 메인 플로우

```
[랜딩 페이지]
    │
    ▼
[카메라 권한 요청]
    ├─── 거부 ──→ [권한 안내 페이지] ──→ 재시도
    │
    ▼ 허용
[카메라 프리뷰 + 모델 로딩]
    │ (TF.js MoveNet 초기화)
    ▼
[캘리브레이션 화면]
    │ (3초 안정 포즈 감지)
    ▼
[게임 선택 메뉴]
    ├──→ [SpacePong]
    ├──→ [FruitSlicer]
    ├──→ [ObstacleDodge]
    └──→ [JumpChallenge]
         │
         ▼
    [3...2...1...GO 카운트다운]
         │
         ▼
    [게임 플레이 (60초)]
         │
         ├─── 시간 만료 ──→ [게임 오버 화면]
         └─── 조건 충족 ──→ [게임 오버 화면]
                                  │
                    ┌─────────────┴─────────────┐
                    ▼                           ▼
             [재도전 (동일 게임)]        [메뉴로 돌아가기]
```

### 화면 전환 조건

| 화면 전환 | 트리거 조건 |
|-----------|-------------|
| 랜딩 → 카메라 권한 | "게임 시작" 버튼 클릭 |
| 카메라 권한 → 캘리브레이션 | `getUserMedia` 성공 + 모델 로드 완료 |
| 캘리브레이션 → 게임 선택 | 3초 안정 감지 완료 또는 "건너뛰기" 클릭 |
| 게임 선택 → 플레이 | 게임 카드 클릭 후 3초 카운트다운 |
| 플레이 → 게임 오버 | 타이머 만료 OR 목숨 0 OR 장애물 충돌 |
| 게임 오버 → 재도전 | "재도전" 버튼 클릭 → 즉시 카운트다운 |
| 게임 오버 → 메뉴 | "게임 선택" 버튼 클릭 |

## 8. 게임 디자인 요구사항

### 8.1 SpacePong — 우주 탁구

| 항목 | 세부 사항 |
|------|-----------|
| **핵심 동작** | 몸 좌우 이동으로 패들 조종 |
| **초기 상태** | 목숨 3개, 볼 속도 = 화면 높이 × 0.55/초 |
| **점수 규칙** | 패들 히트당 5점, 50점마다 속도 ×1.1 |
| **난이도 곡선** | 히트 누적에 따른 점진적 속도 증가 |
| **종료 조건** | 60초 경과 OR 목숨 3개 소진 |
| **접근성** | 패들 너비 화면의 25% (넓은 여유 제공) |

### 8.2 FruitSlicer — 과일 슬라이서

| 항목 | 세부 사항 |
|------|-----------|
| **핵심 동작** | 양손 빠른 스와이프 (speed > 0.3) |
| **과일 종류** | 사과, 수박, 포도, 레몬, 딸기 (5종) |
| **폭탄 비율** | 전체 스폰의 15% |
| **점수 규칙** | 과일 슬라이스 성공 시 10점 |
| **난이도 곡선** | 스폰 간격 1.4초 → 최소 0.6초 |
| **패널티** | 과일 3개 미스 = 목숨 1 감소 / 폭탄 히트 = 즉시 목숨 1 감소 |
| **종료 조건** | 60초 경과 OR 목숨 3개 소진 |

### 8.3 ObstacleDodge — 장애물 회피

| 항목 | 세부 사항 |
|------|-----------|
| **핵심 동작** | 몸 기울기(좌우 tilting)로 파이프 통과 |
| **파이프 갭** | 화면 높이의 32% |
| **갭 위치** | 플레이어 반대 방향 편향 배치 (동적 난이도 조절) |
| **점수 규칙** | 파이프 1개 통과당 10점 |
| **난이도 곡선** | 파이프 간격 2.0초 → 최소 0.9초, 속도 점진 증가 |
| **종료 조건** | 60초 경과 OR 파이프 충돌 |
| **접근성** | 갭 비율 32%는 표준 체형 기준 충분한 여유 |

### 8.4 JumpChallenge — 점프 도전

| 항목 | 세부 사항 |
|------|-----------|
| **핵심 동작** | 실제 점프 동작 인식 (힙 Y가 기준선 20% 이상 상승) |
| **장애물 종류** | 선인장(28×52), 바위(44×36), 스파이크(22×72) 3종 |
| **점수 규칙** | 생존 시간(초) × 10 |
| **물리 엔진** | 초기 점프 속도 820px/s, 중력 1800px/s² |
| **난이도 곡선** | 이동 속도 = 화면너비 × (0.38 + 생존시간 × 0.006) |
| **패럴랙스** | 3레이어 시티 배경 (속도 0.12/0.25/0.55 배율) |
| **종료 조건** | 60초 경과 OR 장애물 충돌 |

## 9. 제약사항 및 리스크

### 기술적 제약

| 제약 | 상세 내용 | 완화 전략 |
|------|-----------|-----------|
| 조명 조건 | 어두운 환경에서 포즈 감지 정확도 저하 | 캘리브레이션 시 밝기 경고 UI 제공 |
| 카메라 품질 | 저화질 카메라(480p 미만)에서 keypoint 신뢰도 하락 | score threshold 동적 조절 (기본 0.3) |
| CPU 성능 | 저사양 기기에서 TF.js WebGL 연산 병목 | frameSkip 옵션 자동 조정, 모바일 감지 시 2배 스킵 |
| 배경 복잡도 | 복잡한 배경에서 신체와 배경 구분 어려움 | 단색/단순 배경 권장 안내 제공 |

### 브라우저 제약

| 제약 | 상세 내용 |
|------|-----------|
| HTTPS 필수 | `getUserMedia` API는 secure context(HTTPS 또는 localhost)에서만 동작 |
| iOS Safari 제한 | iOS 14.5+ 이하에서 WebGL 성능 제한 |
| 카메라 권한 정책 | 브라우저마다 권한 요청 UI 및 정책 상이 |
| 백그라운드 탭 | 탭 비활성화 시 RAF 일시정지 → visibility change 핸들링 필요 |

### 리스크 분석

| 리스크 | 확률 | 영향도 | 완화 전략 |
|--------|------|--------|-----------|
| 모델 로드 실패 (네트워크) | 중 | 높음 | CDN 폴백, 재시도 UI 제공 |
| 포즈 감지 부정확 | 중 | 중 | 캘리브레이션 강제화, 임계값 조정 |
| 모바일 성능 저하 | 높음 | 중 | frameSkip 자동 조절, 낮은 해상도 처리 |
| 카메라 권한 거부 | 중 | 높음 | 설명 강화, 데모 모드(모의 제스처) 고려 |
